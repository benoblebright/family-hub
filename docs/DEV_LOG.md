## 사례 1. 기획 대화를 AI에게 전달하지 못함

- **문제 상황:** claude.ai 기획 대화 공유 링크를 Claude Code에 주었지만, 내장 브라우저가 로그인 페이지로 튕겨서 내용을 읽지 못했다. 다시 로그인했다고 했는데도 같은 화면이 나왔다.
- **AI 활용:** "링크 열어줘봐"라고 다시 요청했고, AI는 브라우저 창을 대화 옆에 띄워 직접 로그인할 수 있게 했다.
- **해결 과정:** 그 창에서 로그인한 뒤 다시 읽게 했다. 이전엔 다른 곳에서 로그인해서 세션이 브라우저 창에 남지 않았던 것이 원인이었다.
- **최종 결과:** 해결. AI가 대화 전체(시장 조사, 구조, 요금제)를 읽고 프로젝트 메모로 정리한 뒤 개발을 시작했다.

## 사례 2. "앱 만들어줘"가 너무 모호함

- **문제 상황:** 처음에 "부모님소통 앱 만들기"라고만 요청했더니, AI가 자녀↔부모님/학부모↔선생님 중 어느 관계인지, 어떤 플랫폼인지 되물었다.
- **AI 활용:** 기획 대화 링크를 근거로 주고, 첫 개발 범위를 고르게 했다. AI가 "부모님 쪽은 전화·ARS만 쓰니 앱은 자녀용 화면"이라고 정리하고 4개 선택지(자녀용 웹앱 / 랜딩 / 프로토타입 / 앱인토스)를 제시했다.
- **해결 과정:** "자녀용 웹앱 MVP"를 골랐다. 이후 "API·vox 연결은 나중에, 그런 거 아닌 것만 먼저"처럼 범위를 끊어서 지시했다.
- **최종 결과:** 외부 연동 없이도 0단계(운영자 수동)로 돌아가는 구조가 먼저 완성됐다. 요구사항을 범위 단위로 끊어 전달하는 게 효과적이었다.

## 사례 3. 한국어 조사가 틀리게 나옴 ("막내이랑", "엄마가" 고정)

- **문제 상황:** "○○이랑 통화하셨다면서요?" 문구를 만들 때 호칭이 "막내"면 "막내이랑"이 되는 문제를 코드 검토 중 발견했다. "엄마가 물어보셨어요"도 호칭이 바뀌면 틀린다.
- **AI 활용:** 받침 유무에 따라 조사를 고르도록 수정을 지시했다.
- **해결 과정:** AI가 한글 유니코드에서 받침 여부를 계산하는 `josa()` 유틸을 만들고(`src/lib/format.ts`), 이랑/랑, 이/가, 과/와가 들어가는 모든 문구에 적용했다.
- **최종 결과:** 해결. "큰아들이랑 / 막내랑 / 엄마가" 모두 자연스럽게 나온다.

## 사례 5. 미리보기 서버가 실행되지 않음

- **AI 활용:** 오류 메시지에 나온 다른 서버 이름들을 보고 원인을 찾게 했다.

- **최종 결과:** 해결. 이후 브라우저로 화면 확인·폼 제출 테스트를 했다.

## 사례 6. 운영자 키가 페이지를 이동하면 사라짐

- **문제 상황:** 처음엔 운영자 화면을 `?key=` 주소로 보호했는데, 운영자 화면이 여러 페이지로 늘어나자 링크마다 키를 붙여야 했고 주소창·기록에 키가 노출됐다.
- **AI 활용:** 운영자 화면 확장(가족 등록·가족 운영·ARS 대본)을 요청하면서 접근 방식 재검토를 지시했다.
- **해결 과정:** `/admin/login`에서 키를 확인하고 httpOnly 쿠키로 저장하는 방식으로 바꿨다. 서버 액션도 쿠키로 검사한다(`src/lib/admin.ts`).
- **최종 결과:** 해결. 로컬에서 `ADMIN_KEY`를 비워 두면 로그인 없이 들어갈 수 있다.

## 사례 7. 테스트 중 폼 입력칸 이름이 안 잡힘

- **AI 활용:** 테스트 결과에서 발견한 문제를 고치도록 지시했다.
- **해결 과정:** 라벨에 `htmlFor`, 입력칸에 `id`를 붙였다.
- **최종 결과:** 해결 (10/21 커밋).

## 사례 9. Firestore 생성 권한 오류 → CLI로 우회

- **문제 상황:** Firebase MCP 도구로 Firestore를 만들려 하자 `Permission 'mcp.googleapis.com/tools.call' denied` 오류가 났다. 새 프로젝트에서 해당 API가 아직 켜져 있지 않은 상태였다.
- **AI 활용:** 같은 작업을 Firebase CLI로 하도록 했다.
- **해결 과정:** `firebase firestore:databases:create "(default)" --location asia-northeast3 --delete-protection ENABLED`로 서울 리전에 생성했다. 리전은 나중에 바꿀 수 없어서 처음부터 서울로 지정했다.
- **최종 결과:** 해결. 단, 보안 규칙 배포는 `firebaserules` API 403으로 아직 실패 → 사례 10.

## 사례 11. 서버리스에서는 파일 저장이 사라짐 → Firestore로 교체

- **문제 상황:** 로컬에서는 `data/db.json` 파일에 저장했는데, Vercel 같은 서버리스 환경은 요청마다 새 인스턴스가 뜨고 파일 시스템이 유지되지 않아 배포하면 데이터가 남지 않는다.
- **AI 활용:** "화면 코드는 그대로 두고 저장소만 바꿔 달라"고 범위를 정해 지시했다.
- **해결 과정:** AI가 `readDB / updateDB` 두 함수만 바깥에 보이게 하고, 안쪽을 파일 저장소와 Firestore 저장소 두 가지로 나눴다(`src/lib/db.ts`). Firebase 키가 있으면 Firestore, 없으면 파일. Firestore 쪽은 바뀐 문서만 쓰고, 배열 순서는 `_o` 필드로 보존하며, Firestore가 거부하는 `undefined` 값은 쓰기 전에 제거한다. 음성 파일도 같은 방식으로 Cloud Storage/로컬 폴더를 고른다.
- **최종 결과:** 로컬은 키 없이 그대로 동작. 한계: 요청마다 컬렉션 전체를 읽어서 데이터가 많아지면 느려진다(과제 규모에선 문제없음, 2단계에서 쿼리 단위로 바꿀 예정). 여러 인스턴스가 동시에 쓰면 나중 쓰기가 이길 수 있다.

## 사례 12. 서버가 UTC라서 날짜·요일이 어긋날 위험

- **문제 상황:** "이번 주 월요일", "오늘 안부 문자", 통화 기록 입력 시각 기본값이 모두 서버 시간대 기준으로 계산되고 있었다. 맥(KST)에서는 맞지만 Vercel(UTC)에 올리면 오전 9시 전에는 날짜가 하루 밀린다.
- **AI 활용:** 배포 전에 시간대 의존 코드를 전부 찾아 KST로 고치도록 지시했다.
- **해결 과정:** AI가 `getDay()`, `toISOString().slice(0,10)`, `getTimezoneOffset()` 쓰는 곳을 검색해 찾고, `kstDate / kstAt / weekStart / kstInputNow` 유틸로 바꿨다(`src/lib/format.ts`). 시각은 `"2026-10-21T09:00:00+09:00"`처럼 +09:00을 붙여 만든다.
- **최종 결과:** 해결. 시뮬레이터에서 09:00 발송 → 11:00 재문자 → 12:00 확인콜 시각이 KST로 정확히 찍히는 것을 확인했다.

## 사례 13. 엄마 시뮬레이터: 답장 문자가 화면에 안 보임

- **문제 상황:** 시뮬레이터에서 엄마가 "김장 같이 할 사람 있니?"를 보냈는데, 질문은 만들어졌지만 "자녀들에게 물어볼게요" 답장 문자와 "형제들에게 질문을 보냈어요" 로그가 화면에 없었다.

- **최종 결과:** 해결.

## 사례 15. 서비스 계정 키를 받지 못해 Firestore 연결이 막힘

- **문제 상황:** Firestore를 쓰려면 서비스 계정 키(JSON)가 필요했다. `.env.local`에 넣었다고 생각했지만 AI가 확인해 보니 파일이 없었고, 다운로드 폴더에도 키 파일이 없었다. 안내받은 명령어를 붙여 넣었을 때는 예시 파일명(`the-key-file.json`)을 그대로 써서 "파일 없음" 오류가 났다.
- **AI 활용:** 파일이 어디 있는지 대신 찾아보게 했고, 그래도 없자 "대신 만들어 달라"고 요청했다.
- **해결 과정:** AI가 키 내용을 화면에 출력하지 않는 방식으로 진행했다. `gcloud iam service-accounts keys create`로 임시 폴더에 키를 만든 뒤, 한 줄 JSON으로 바꿔 `.env.local`(권한 600)에만 쓰고 임시 파일은 바로 지웠다. `.env.local`이 git에서 제외되는지도 확인했다. 예시 파일명이 실제 이름처럼 보여 생긴 혼동은, 다운로드 폴더에서 최신 키 파일을 자동으로 찾는 명령으로 바꿔 안내했다.
- **최종 결과:** 해결. 개발 서버 로그에 `Environments: .env.local`이 찍히고, 첫 요청에서 데모 데이터가 Firestore 12개 컬렉션에 적재된 것을 문서 개수로 확인했다.

## 사례 16. Firestore 모드에서 같은 시나리오 다시 테스트

| 확인 | 결과 |
|---|---|
| 첫 요청 시 시드 적재 | families 1, children 3, checkins 20 등 12개 컬렉션 생성 |

## 사례 17. Cloud Storage 버킷이 없어 음성 답장이 통째로 실패할 위험

- **문제 상황:** 새 프로젝트는 결제 계정(Blaze)이 아직 연결되지 않아 Storage 버킷이 없다. 이 상태에서 음성을 첨부하면 업로드 오류가 나면서 글 답장까지 함께 저장되지 않는 구조였다.
- **AI 활용:** 버킷 상태를 확인하게 하고, 음성 저장이 실패해도 서비스가 멈추지 않게 지시했다.
- **해결 과정:** `saveAudio`가 오류를 잡아 서버 로그에만 남기고 `undefined`를 돌려주도록 바꿨다. 글·버튼 답이 있으면 그것만 저장하고 "음성은 저장하지 못했어요"라고 알려 주고, 음성만 보낸 경우엔 글로 남겨 달라고 안내한다. 브라우저에서 가짜 음성 파일을 넣어 제출해 로그 `The specified bucket does not exist`와 안내 문구가 뜨는 것을 확인했다.
- **최종 결과:** 장애는 막음. 음성 저장 자체는 Blaze 연결 + Storage 시작 후 동작 예정(한계로 남음).

## 사례 22. 배포본 응답이 2.5~5초 — 요청마다 DB 전체를 네 번 읽음

- **문제 상황:** 서울 리전으로 바꾼 뒤에도 가족 홈이 2.5~5초 걸렸다.
- **AI 활용:** 리전 말고 코드 쪽 원인을 찾게 했다.
- **해결 과정:** 가족 홈 한 번 열 때 `findChild`(읽기) → `processFamily`(읽기+쓰기) → `readDB`(읽기) → `findChild`(읽기)로 컬렉션 14개를 4번 읽고, 일이 없어도 `lastTick` 때문에 매번 썼다. 안부 문자 처리(`tick`)는 같은 날짜·단계를 두 번 처리하지 않으니 `lastTick`만 바뀔 땐 쓰지 않아도 결과가 같다. 그래서 처음 읽은 데이터로 미리 계산해 보고 실제로 일어날 일이 있을 때만 쓰고, 읽은 데이터를 페이지까지 넘겨 다시 읽지 않게 했다.
- **최종 결과:** 로컬(Firestore 연결) 기준 1.3초 → 0.1~0.5초. 배포본은 재배포 후 측정.

## 사례 24. "형제" 서비스로 보이는 문구 → 형제·가족·친구 누구나

- **문제 상황:** 화면 곳곳이 "형제들에게", "자녀분들께"처럼 형제·자녀만 쓰는 서비스로 읽혔다. 가족·친구도 함께할 수 있어야 한다.
- **AI 활용:** "형제 가족 친구 이렇게 폭넓게" 바꾸라고 지시했다. 1차로 AI가 "형제"를 "가족"으로만 일괄 치환해서 친구가 여전히 빠졌고, 조사도 "가족는", "가족가"로 깨졌다. 다시 "누구나 해당되게" 하라고 지시했다.
- **해결 과정:** 사람을 가리키는 표현을 전수 검색(형제·자녀·가족들·가족 모두·가족 중 등)해서 "함께하는 사람들", "모두", "가족방 사람들", "누구든 한 분이"로 바꿨다. 서비스 이름(가족방·가족 홈·가족신문)은 그대로 두었다. 호칭을 비우면 이름을 호칭으로 쓰게 해 "이모", "친구"도 자연스럽게 넣을 수 있게 했다.
- **최종 결과:** 해결. 기계적인 일괄 치환은 의미와 조사를 망가뜨릴 수 있어서, 바뀐 줄을 하나씩 확인해야 한다는 교훈.

## 사례 26. 요금제 재설계 — AI가 처음 잡은 가격이 비쌌던 이유 따져 보기

- **문제 상황:** "가장 싼 게 왜 24,900원이지?"라는 의문. 기획 때 요금은 vox AI 통화 원가(가구당 월 1.25만~1.7만 원)에서 거꾸로 계산한 값이었다.
- **AI 활용:** 계산식을 그대로 보여 달라고 했고, 경쟁 서비스(클로바 케어콜 돌봄 서비스 1인 4,400원)를 근거로 다시 따졌다. AI는 처음에 4,400원을 공개 자료에서 찾지 못했는데, 내가 대행사(세종네트웍스) 페이지 링크를 주자 요금표(기본형 건당 770원, 돌봄 서비스 1인 4,400원)를 읽어 건당 원가를 비교했다.
- **해결 과정:** 원가를 정하는 건 엔진이 아니라 **통화 횟수**라는 걸 확인하고, 콜 횟수로 요금제를 나눴다(주 1회 9,900 / 주 2회 16,900 / 주 3회+종이신문 29,900원). "실시간 통화 연결"은 분당 144원 이상이 드는데 무료 알림으로 대체 가능하고, 가족 통화를 녹음하면 서비스가 제3자가 돼 통신비밀보호법 문제가 있어 빼기로 결정했다. 회고록은 별도 상품으로 분리. AI가 중간에 "주 2회 콜 8,900원(문자 포함)"이라고 잘못 말했다가 정정한 것도 확인했다(실제 9,600원).
- **최종 결과:** 세 요금제 모두 가구당 남는 비율 30~40%. 계산은 `docs/PRICING.md`에 정리.
